# Document benchmark — corpus and replay harness, semantic evaluation pending

This benchmark starts from ordinary files, not canonical records disguised as
documents. Twenty generated families cover the mission's A–T list: contracts,
invoices, returns, amendments, credits, spreadsheets, email, genuine raster scans,
hybrid pages, ambiguous dates, missing pages, noise and a separately withheld
response. The generator uses pypdf/openpyxl and Poppler `pdftoppm` for rasterizing
synthetic pages; no OCR or model API is added to the engine.

Ownership:

- `benchmarking/document_corpus.py`: scenario truth and independent document rendering.
- `benchmarking/document_runner.py`: only public sources and supplied proposals.
- `benchmarking/document_scoring.py`: private truth, read after observations freeze.
- `benchmarking/document_renderers.py`: readable PDF, raster and deterministic XLSX bytes.

Generate and establish the deliberately empty-extractor baseline:

```sh
python run_document_benchmark.py generate scratch/doc-dev --split DEV --seed 7421
python run_document_benchmark.py run scratch/doc-dev/public scratch/doc-run --split DEV
python run_document_benchmark.py score scratch/doc-dev scratch/doc-run
```

The runner can instead accept `--submissions DIRECTORY`, with one supplied
`againward-rental-document-case-v1` package per opaque case ID (`ID.json`). It
snapshots the actual public files, demands the exact batch identity, revalidates
source-bound proposals, applies the supplied reviews and invokes the actual
Rental adapter and ledgers. No automatic semantic proposals or human approvals
are generated by this harness. A missing or rejected submission abstains; an
unresolved financial group does not become numeric zero.

## Current measured result, not acceptance

DEV seed 7421 routing baseline: all 20 folders traversed; TP 0, FP 0, FN 6,
TN 14; supported-discrepancy recall **0**. Correct abstention on 9/9 required
abstention cases. Annotated-field recall **0**. Precision is null because no
prediction was made. Only 9/20 exact financial outcomes match, all by abstention.
This proves a useful honest baseline and routing coverage, not intelligence.

The independent adapter fixture additionally replays supplied annotations into
an exact EUR 150 discrepancy and preserves its source chain. It is a software
contract test, **not** a model-quality result on the generated corpus.

Only three decisive contract fields per generated case are currently annotated.
Dates, full entity-pair metrics, unknown preservation, double count, retained
finding chains and lifecycle metrics remain unmeasured in this harness and are
reported as null. Existing lifecycle/financial unit tests do not substitute for
these missing document-level metrics. Family T currently supplies a withheld
answer fixture; the runner does not yet execute WAIT/RESUME on that corpus case.

## Split and contamination discipline

DEV, ADVERSARIAL and HOLDOUT are separate generation invocations with separately
selected seeds. HOLDOUT runner requires a clean committed engine and checks it
again at completion. Observations and truth have hashes; scorers refuse changed
inputs and refuse overwriting a previous score. These are procedural safeguards,
not filesystem isolation against a malicious participant. A reader who inspected
the private truth must not describe its subsequent proposals as blind holdout.

Do not tune on HOLDOUT scores. Freeze code, extraction protocol and review rules
first, run a fresh participant context with only public files, then score once.
No HOLDOUT accuracy is claimed yet. No paid provider or real client data is used.
